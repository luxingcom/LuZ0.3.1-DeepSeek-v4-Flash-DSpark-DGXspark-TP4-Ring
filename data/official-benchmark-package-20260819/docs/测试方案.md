# DeepSeek-V4-Flash 4×DGX Spark TP4 对比测试方案

> 版本：2026-08-19 · 供第三方环境对比测试使用
> 目的：在相同口径下复现本部署的基准数据，评估目标环境与参考环境（4×DGX Spark TP4）的性能差异

---

## 1. 测试目标

| 指标 | 参考值（本部署 8/19 复测，decode-only 中位 | 最优） |
|---|---|---|
| 单流（fox 文本，512t 输出） | 97.1 \| 124.0 t/s |
| 并发聚合 C8 | 286.3 \| 302.9 t/s |
| 并发聚合 C12 | 342.8 \| 358.2 t/s |
| Agent 场景平均 | 81.3 \| 84.6 t/s |

## 2. 环境要求

- 模型：DeepSeek-V4-Flash-0731（NVFP4，1M context）
- 推理框架：vLLM V1（VLLM_COMPILE + MTP 投机 n=5）
- 服务：OpenAI 兼容 API（`/v1/chat/completions`）
- 关键配置：`max_num_seqs=16`、`max_num_batched_tokens=8240`、`gpu_memory_utilization=0.82`、`kv_cache_dtype=nvfp4_ds_mla`、`enable_flashinfer_autotune=True`
- **客户端**：任意机器，能访问 API 即可（脚本用 requests）

## 3. 关键口径（必须一致，否则数据不可比）

### decode-only 计时
- **自首 token 出现后开始计时**（`t_first` = 第一个内容 token 到达时间）
- 结束 = `usage` 上报（`stream_options.include_usage=True`）
- 每流速度 = `(completion_tokens - 1) / (t_last - t_first)`
- **排除 prefill 时间**（prefill 只影响 TTFT，不影响 decode 吞吐）

### 并发聚合
- 每流 decode 速度取**中位数**，聚合 = `中位 × C`
- 每项**至少 5 轮**（本参考数据为 5-10 轮）

### 去冷启动 / 预热
- **必须预热**：测试前先发 20-30 个请求（触发 kernel JIT 编译收敛）
- 充分预热后数据显著更高（本部署 C8：预热前 242.6 vs 预热后 286.3）

## 7. 常见坑

1. **口径不一致**：端到端（含 prefill）数字会低 30%+，必须用 decode-only
2. **不预热**：编译窗口期数据偏低（C8 242.6 vs 286.3）
3. **单流波动**：fox 文本 79-124 波动大，需 10 轮取中位
4. **并发取均值 vs 中位**：取中位（均值被慢流拉低）
5. **多节点 TP**：确保所有 worker 都参与（GPU 利用率 90%+），否则聚合偏低
