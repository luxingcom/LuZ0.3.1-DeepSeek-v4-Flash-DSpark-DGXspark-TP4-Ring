## 🔍 根因分析（5 Why × 3）

**#1 collective_rpc 断言**
W1 初始化 collective_rpc 断言失败 → TP=2 建不起来
W2 worker 未走 run_headless 分支（serve.py:196-210）→ 分布式初始化参数错
W3 启动脚本未给 rank1 设 --headless/HEADLESS=1
W4 脚本手写/复制粘贴、双机各自维护，无"角色一致性"校验
W5 **无 preflight 校验层**：无参数模板化、无角色断言、无脚本 diff
→ 系统性缺陷：**部署前置校验缺失**

**#5 pkill 误杀（复发 2 次）**
W1 pkill -f vllm 后 ssh 会话被杀
W2 -f 按完整命令行匹配，执行命令的会话自身含该串
W3 用进程名通配清理，而非容器名/PID
W4 无进程管理规范，绕过了 docker rm -f 既定手段
W5 **危险命令无防护、规范未制度化（复发即未闭环）**
→ 系统性缺陷：**进程管理策略缺失**（现已全项目禁用 pkill -f，统一 docker rm -f，✅ 已落实）

**#6 双 worker 事故**
W1 双机同以 headless 启动，无 head 节点 → 集群失败
W2 head(60) 跑的是 worker 版脚本（HEADLESS=1）
W3 worker 脚本被 scp 到 head 覆盖
W4 双机脚本仅 rank/HEADLESS 差异，无角色标记，手动 scp 无法辨识
W5 **无脚本校验和/角色签名/分发版本控制**，"严禁互拷"仅为口头纪律
→ 系统性缺陷：**脚本一致性校验缺失**

**共性结论**：三次最严重事故同根——**部署前置校验缺失 + 脚本/进程管理无机制化**。

## 🛡️ 预防措施（防复发机制）

1. **Preflight 门禁**：任何启动路径必须经过 preflight.sh（角色断言、env 基线、镜像 digest、RoCE 链路、权重抽样、启动顺序守护），失败即拒启。
2. **机制化替代人肉纪律**：脚本入 git + SHA256SUMS + hostname/NODE_RANK 守卫（防互拷）；CRLF 门禁（gitattributes eol=lf + pre-commit）。
3. **进程管理规范**：全项目禁用 pkill -f（已落实），统一 docker rm -f <容器名>；runbook 禁止危险通配。
4. **自愈与可观测**：容器 restart 策略 + healthcheck + 日志卷 + 至少 4 条告警规则（容器 Exited、/health 5xx、KV 水位、节点 down），并做告警链路验证（非仅配置）。
5. **回滚制度化**：8000↔8001 双向回滚 Runbook + 上线前实测 RTO 一次。
