# 4 并发 131K PR 折算与"面板 8k"取证报告

- 日期：2026-08-14（UTC 06:10–06:28 测试窗口）
- 环境：TP4 生产 b12x+MXFP4，Prometheus <NODE_IP>:8191（仅采集 01:8001 单实例，无多 rank 重复计数），Grafana <NODE_IP>:3000
- 数据源：`_tessa_tp4_bench/CONC_COMPARE/prefill4_131k_thread.json` + Prometheus range 查询（60s/5s 步长）+ Grafana 面板定义

## 1. 折算 PR（用户问）

| 项 | 值 |
|---|---|
| 总 tokens | 534,772（4 × 133,682~133,705，随机前缀） |
| 墙钟（并发开始→全部结束） | 221.98s |
| **折合 PR（墙钟聚合）** | **534,772 / 221.98 = 2,409 tok/s** |
| per-request 均值 | 133,693 / 219.15s ≈ 610 tok/s |
| 引擎口径（Σprefill_time = 872.1s） | 534,772 / 872.1 = 613 tok/s |

三数自洽：per-request ≈ 610 ≈ 引擎口径 613（面板干净读数）；4 并发并行复用引擎 → 墙钟聚合 2,409 ≈ 613 × 3.9（并发度 4 的复用比，Σprefill_time 872s ≈ 4 × 218s）。

## 2. 面板"8k"取证结论：缓存命中污染的假象

### 面板公式（Grafana "预填充有效速度 Prefill t/s"）
```
sum(increase(vllm:request_prompt_tokens_sum[5m]))
/ clamp_min(sum(increase(vllm:request_prefill_time_seconds_sum[5m])), 1)
```

### 复现结果（60s 采样）
| 时刻 UTC | 面板读数 t/s |
|---|---|
| 06:13 | 9,449 |
| 06:14 | **8,168** |
| 06:15 | **8,108** |
| 06:16 | 5,965 |
| 06:20–06:23（4 并发主测试中） | 2,022–2,047 |
| 06:25–06:28（窗口干净） | **613** |

### 根因：窗口混入缓存命中批次（秒级证据）
- 06:12:30：pt +181,010，其中 **cached +171,264（94.6% 命中）**，pf 仅 +6.4s
- 06:14:00：pt +534,375（≈4×133,594，**4 并发但命中缓存 84.3%**，cached +450,304），pf 仅 +50.4s
- 06:14:05：pt +133,600，cached +133,376（99.8% 命中），pf +0.4s
- 主测试（随机前缀，cached=0）在 06:23:30–06:23:40 计入 534,772 tokens，pf 872.1s

面板 06:14–06:15 的 5m 窗口 [06:10, 06:15]：
- 分子 = 985,728 tokens（其中 **754,944 为缓存命中，占比 76.6%**）
- 分母 = 121.5s（缓存命中 tokens 几乎零引擎成本）
- 比值 = **8,113 t/s ≈ 面板 8.1–8.2k** ✓

## 3. 结论

1. **4 并发 131K 冷 prefill（随机前缀）真实吞吐 = 2,409 tok/s（墙钟）**，对应每请求 ~610 t/s。
2. **面板 8k 不是真实速度**：是 5m 滑动窗口吞入了测试准备期"缓存命中批次"的 75.5 万 tokens（几乎不耗时），分子虚大、分母虚小所致。
3. **面板干净后的 613 t/s = per-request 平均口径**（Σtokens/Σprefill_time 等价于每请求均值），不是聚合吞吐；要读聚合吞吐应看墙钟口径或×并发度。
4. 交叉验证：主测试窗口 pf 增量 872.1s 与 4×per_req_elapsed（219.1/220.0/215.5/222.0）吻合，Prometheus 数据自洽。

## 4. 后续建议
- 面板增加 `prompt_tokens_cached` 抵消项（分子减缓存命中 tokens）或标注"含缓存命中"
- 大请求测试前清空前缀缓存（`/prefix_cache` 或换随机前缀），避免窗口污染
- 如需面板直接展示聚合吞吐，可加 `* sum(vllm:num_requests_running)>0` 或改用墙钟窗口速率
