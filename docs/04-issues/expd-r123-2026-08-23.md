### 2.3 模式分布判定

- **修复前**：慢×3（4.43/4.25/4.27）/ 中×2（3.07/3.48）/ 快×0；**修复后**：慢×1 / 中×1。
- 首请求 TTFT 明显双簇：**慢簇 4.25-4.43s**（4 次）vs **中簇 3.07-3.48s**（3 次），无 <3s 快臂（对照上日 14:16 会话 2.88s 快臂——快臂本窗口未抽中，样本量原因）。
- 稳态 panorama 4K TTFT：慢臂 2.96-2.98s vs 中臂 2.88-2.90s（差 ~3%）；PR：慢臂 2753-2768 vs 中臂 2832-2853（差 ~3.4%）。
- **结论：重启级模式方差复现确认**——warmup 首请求 TTFT 差 ~40%，稳态 PR 差 ~3.5%；"模式"主要体现在首 prefill（一次性成本：cudagraph/JIT/内存 first-touch），稳态差异较小但系统性存在。

### 2.4 H2 证据判定（libncclpin 按名 pin 漏网）

| 轮 | 漏网/越界明细 | 类型 |
|---|---|---|
| R2 | 04: `NCCL IbAsync 0` TID=2507910 **ALLOWED=5-19**（同批 IbAsync 1/2/3 及其余 23 条 NCCL 线程均 8-9；01/02/03 同名线程全部正常） | 按名 pin 漏网（pin 未生效） |
| R3 | 01: `VLLM::EngineCor` 线程 TID=458031 **PSR=7**（ALLOWED=5-19，主线程 15-19 正常） | 落点越界（pin 漏网线程落 5-9 带） |
| R4 | 01: `VLLM::EngineCor` 线程 TID=726422 **PSR=5**（同上型） | 落点越界——**与上代（08-22 13:33 代，TID 778833 PSR=5）完全同型** |
| R7 | 01: `VLLM::EngineCor` 线程 TID=1616462 **PSR=11** | 落点越界 |

- **H2 机制实锤**：漏网按重启随机出现（4/7 轮、不同节点不同线程、漏网对象含 NCCL IbAsync 与 EngineCor 命名线程），无法由部署一致性解释（四机 MD5=v8 一致）→ 竞态漏网成立。
- **但 H2 与臂模式不相关**：慢臂（R1/R4/R5/R7）中 2/4 有越界；中臂（R2/R3/R6）中 2/3 有越界。慢臂 R1/R5 完全干净仍落慢簇。→ **H2 非模式方差主因**（n=7；上代 baseline C1 方差 ±20% 恰逢 pin 异常代的相关性未在本窗口复现）。
- 结构性观察：每代 EngineCor 命名线程存在多条（1-6 条），其中 ALLOWED=5-19 的占比在四节点普遍存在（主线程恒 15-19）——shim 对非主 EngineCor 线程的覆盖本身不完整，属 v8 设计现状。

## 4. 结论与建议

1. **模式方差根因未定论但范围收窄**：H2（pin 漏网）排除为主因；剩余头号候选为 NCCL channel→NIC 口映射抽签（环网 2 收 2 发）及其他重启期抽签变量 → **建议下一窗口执行实验 C**（NCCL_DEBUG=INFO 通道建立日志 × 臂模式 × RDMA 分口流量），协议见 slowround 报告 §5。
2. **R4（libncclpin v9）定位调整**：H2 漏网率本窗口实测 4/7 重启（≈57% 重启至少 1 处），是真实卫生缺陷，但因与模式不相关，**建议从"慢轮专项根治项"降级为常规卫生修复**，与实验 C 窗口合并排期。
3. **R5（nohz_full=8-9）维持原排序**（实验 A 之后评估）。
4. **运维提示**：01 上并行 B12X recovery 构建流（fi-eugr-prep）曾抢 GPU 显存致首轮重启失败——后续窗口前建议与并行工作流做 GPU 资源协调声明。
