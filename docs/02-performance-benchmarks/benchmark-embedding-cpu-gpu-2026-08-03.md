## 📊 实测数据（1000 条混合文本：短 20% + 中 60% + 长 20%）

| 模式 | batch | 吞吐(条/s) | 单条延迟 | 10 万条耗时 |
|---|---|---|---|---|
| CPU(8020) | 1 | 1.84 | 543ms | — |
| CPU | 8 | 2.97 | 337ms | — |
| CPU | 16 | **3.36（最优）** | 298ms | 8.3h |
| CPU | 32 | 3.09 | 323ms | — |
| CPU 全量 1000@32 | 3.15 | ~317ms | **529min（8.8h）** |
| GPU(fp16) | 1 | **30.7（最优）** | 32.5ms | 54min |
| GPU | 8 | 21.0 | 47.6ms | — |
| GPU | 16 | 21.7 | 46.2ms | — |
| GPU 全量 1000@32 | 18.9 | ~53ms | **88min（1.5h）** |

**GPU vs CPU**：单条延迟 16.7×（543→32.5ms）；batch32 吞吐 6.0×（3.09→18.7 条/s）；10 万条 529→88min = 6.0×

## 🔍 检索部分（可忽略）

- 10 万 × 1024 维 float32 = 410MB，numpy 暴力点积（归一化向量即 cosine）
- 单 query 3.9ms（含 top10 ~4.8ms）；1000 query 0.26s（含 top10 0.51s）
- **检索 < embedding 生成的 0.01%**——瓶颈在 embedding 生成，检索无需优化

## ⚠️ 更正与风险记录

1. **"torch cu130 已装"不属实**（此前部署报告表述有误）：全盘无 CUDA torch，仅 CPU 版。已自建 `/home/<USER>/embed-gpu-venv`（torch 2.13.0+cu130+ST，fp16 加载 1.2GB、峰值 5.2GB）并保留可复用；triton 缺 Python.h 已解包 deb + 环境变量绕过

3. 首轮 batch1 异常（18.7s）系残留并发客户端打满 CPU（1091%）所致，已清理重测
