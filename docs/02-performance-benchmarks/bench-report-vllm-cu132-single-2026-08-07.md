## 1. 测试口径与方法学（先读）

- **TP1 vs TP2 口径说明（核心）**：
  - 正确性（GSM8K）与并行度无关 → 可直接对标 95.0%±0.5%
  - 吞吐**不可等比换算**：TP2 c5 80.8-96.5 t/s 为双卡 spec decode 聚合；TP1 无 NCCL 通信但 decode 计算减半、内存带宽同池竞争 → 只记录为独立 TP1 基线，或按「同用例性能比」对比
  - 模型加载可行性：156G FP8 vs 121G 统一内存 → 记录 offload/量化/分片方式与 KV 可用量
- 铁律：随机前缀强制、温度统一（GSM8K=0.6）、max_tokens=128、流式+usage、同硬件同口径

## 6. 与 TP2 基线换算归因

| 指标 | TP2 历史基线 | TP1 实测 | 换算/归因 |
|------|--------------|----------|-----------|
| GSM8K | 95.0% | __ | 并行度无关，直接对标 |
| c5 t/s | 80.8-96.5 | __ | decode 并行度 1/2 + NCCL=0 + 内存带宽竞争 + prefill 分摊；不采用 2× 等比 |
| TTFT | 32K 口径 | __ | prefill 单卡 vs 双卡切分 |

- 归因模板句：实测差值由「decode 并行度 / 通信开销 / 内存带宽竞争 / prefill 切分」四因子解释；先拆时间占比再下结论（引用 runbook §4.8 大 ctx 归因规范）

## 7. 结论三段式（标准句式，勾选一项）

- ✅ **通过**：GSM8K ≥94.5% 且 e2e 0 错误，吞吐 ≥TP1 换算预期下限（或 ≥同用例 TP2 性能比阈值），TTFT 合理，长稳 4h 无卡死/OOM，拉起 ≥80% → **建议推进生产灰度**。
- 🟡 **有条件通过**：正确性与稳定性达标，但吞吐/首载/TTFT 单项未达阈值（如 <换算基线 90%），且根因已定位（如 PTX 首载、sm_121 非原生、cache 未预热）→ **生产暂缓，满足条件 X 后复审**。
- ❌ **不通过**：GSM8K <94.5% / 非偶发错误 / 启动或 NCCL 不可恢复 / OOM 频发 → **暂缓 cu132，回滚 cu130，记录根因并更新 ADR**。
