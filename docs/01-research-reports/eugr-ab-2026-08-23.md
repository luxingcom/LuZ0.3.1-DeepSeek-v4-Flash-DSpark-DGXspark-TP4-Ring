## 1. 口径更正（重大）：生产 M1 实际加载官方 checkpoint，非 modelopt NVFP4

任务书与 prep 报告的"头号对齐风险（生产用 modelopt NVFP4 checkpoint vs Eugr BF16+FORCE_A8）"前提与实际不符【实测】：

- 生产 M1 实际挂载 = `<INSTALL_DIR>/models/deepseek-v4-flash-0731` → `/home/<USER>/models/deepseek-v4-flash-0731`（156GB 官方发布版）：`quantization=deepseek_v4_fp8`（FP8 block linear + **MXFP4 experts** + ue8m0 scales），启动行 `Using 'B12X_MXFP4'`，权重占存 40.5 GiB。modelopt NVFP4 目录（165GB，producer dsv4-nvfp4-experts-mtp-fallback）在盘但**非当前生产挂载**。
- Eugr 源码原生 dispatch 同款【实证-源码】：`DeepseekV4FP8Config.override_quantization_method` 拦截 `quant_method=fp8` + `model_type=deepseek_v4`；`expert_dtype=fp4` + `moe_quant_algo≠NVFP4` → Mxfp4MoEMethod。启动实证：`Using 'B12X' Mxfp4 MoE backend` + `B12X MoE force-A8 enabled: using quant_mode=w4a8_mx for E8M0 FP4 weights`，权重 40.93 GiB（≈生产 40.5）。
- **结论：双臂同权重公平 A/B 成立，无需 confound 口径**。附带发现：Eugr 也原生支持 modelopt NVFP4（`ModelOptNvFp4FusedMoE` 按 `moe_quant_algo=NVFP4` 精确键控）——若未来生产切换 NVFP4 权重，Eugr 栈无需改造【实证-源码】。

## 4. 判决（任务判据逐条）

| 判据 | 阈值 | 实测 | 判定 |
|---|---|---|---|
| PR 四档（同模式口径） | ≥ +5% | +0.4~+4.0%（中值 +1~3%） | ✗ |

**判决：No-Go——attention b12x 化（B12X_MLA_SPARSE + 整套 Eugr V2+AOT 栈）不值得 backport 立项评估，记录关闭。**

### 4.1 判读细节（供未来复盘）

1. **attention 本身大致持平略优**：剔除栈混杂后（同权重同模式同 NCCL），prefill +1-4% 说明 B12X_MLA_SPARSE 相对生产 trtllm sparse MLA 无显著优势——生产现役 attention 路径已接近该模型在 GB10 的 prefill 上限区间。
2. **真正的高并发短板在 decode 步频**：C1 持平 + C12 坍塌的组合指向 batch 维 kernel/调度扩展性问题（W4A8 MoE 动态 launch？V2 runner 调度？dspark verify 路径？）——本实验未做 kernel 级归因（止损纪律，且不影响判决方向）。
3. **方向性正增益的替代收割路径**（更优 ROI）：阶段 3b 已证 W4A4+ws-dedup prefill +6~8%（W4A4 甜点区）——同量级增益无需换栈。
