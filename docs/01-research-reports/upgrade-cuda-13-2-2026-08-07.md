## 6. 回滚 Runbook

### 触发条件（任一命中即回滚）
| 指标 | 回滚阈值 |
|------|---------|
| GSM8K | <94.5% |
| e2e / 网关错误 | 出现非偶发错误 |
| 吞吐 | <旧基线 90% |
| 拉起成功率 | 连续 2 次失败，或 5 次中 ≥2 失败 |
| 稳定性 | 长稳卡死 / OOM / NCCL 不可恢复 |

### 回滚步骤（层级化）
1. **容器级（分钟级，首选）**：
   - vLLM/embed：回切旧 tag（0.2.1-v026.0 / 0.2.0-v026.0-bak 已在 .58 保留）；执行 rollback 脚本（P1 行动补齐）后重跑 G1-G5 确认恢复
   - comfyui：回旧镜像 tag
   - 注意：vLLM TP2 回滚必须双机同 tag 成对操作，head 先，禁止单边
2. **toolkit 级（秒级）**：`update-alternatives --config cuda` 切回 13.0（仅本机 toolkit 升级场景）
3. **驱动级（兜底）**：本方案不涉及驱动升级；若未来 595 实验后需恢复，走 NVIDIA 官方源/DGX OS 通道（禁手动 .run），需维护窗口 + 带外控制台
4. **回滚后**：记录根因 → 更新 ADR 与 Runbook v1.2 → 通知业务方恢复

## 7. 已知风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 新 vLLM 镜像未就绪 | 阻塞 B/C 阶段 | 提前锁定 tag 并预下载到 .58 registry |
| 新镜像无 sm_121 原生仍走 PTX | 吞吐劣化 | C4 重点观测；阈值 <90% 即回滚 |
| 启动竞态/NCCL 偶发卡死 | 拉起失败 | C1 严格 SOP、禁止单边重建、NCCL_DEBUG 留证 |
| torch cu132 破坏 embed 依赖 | embed 回归 | D2 前置验证；embed 与 vLLM 分开升级 |
| sm_121 warmup 门控空转（GB10 SM120 backend 不在 warmup 白名单，曾致长生成卡死） | 推理卡死 | canary 复测 DeepSeek 类模型长生成；升级前必须验证 |
| 首次 JIT/自动调优慢 | 启动时间长 | JIT cache 持久化 + cache 路径含 CUDA 版本分键（防 13.0/13.2 误载） |
