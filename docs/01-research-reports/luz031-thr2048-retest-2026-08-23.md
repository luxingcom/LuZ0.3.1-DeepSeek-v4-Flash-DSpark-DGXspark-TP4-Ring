## 0. 一页结论（三句话定论）

1. **threshold 2048 判决：不采纳（🔴 PR 单流恶化，DE/并发持平）**。防模式方差后（A1/B1/A2/B2 四臂，thr2048×2 + thr4096×2，全部 MODE=OK 无慢轮），PR 四档 thr2048 全面低于 thr4096：**-5.8% / -5.5% / -4.9% / -2.8%**（4K/16K/32K/64K），超 ±3% 采纳门 → 维持生产 thr4096。
2. **归因**：PR 恶化 = chunked prefill 步数翻倍（8.2K 档 2048→5 步 vs 4096→3 步）+ M_e 减半（48 vs 96）→ B12X 带宽效率下降 + 每步固定开销（AR/权重读/attention）重复摊薄；**DE 持平**（step_eff -1.1%/-1.3%、步时 +0.8% 逐字相同）——raw tput 差由接受率运气（tokens/step -7.9%/-5.4%）解释，非 threshold 效应。
3. **方法学有效**：本窗口 thr4096 双臂复现采纳带（PR 2973/2954/2827/2552 vs 采纳 2950.5/2943.6/2834.2/2550.0，**±1% 内**）→ 环境与口径一致，thr2048 对比可信。**剂量-反应单调（1024<2048<4096）**与 threshold-retest 2026-08-22 一致，4096 仍是 batched=4096 下最优剂量点。

## 1. 方法：交错 A/B 4 臂协议（防模式方差）

> 依据 threshold-retest 2026-08-22 教训：重启级模式方差（±8-13%）会混杂单臂对比，必须交错 A/B + 每形态 ≥2 臂独立重启。

| 臂 | threshold | 用途 | 模式探针首 4K TTFT | 模式 |
|---|---|---|---|---|
| A1 | 2048 | thr2048 第 1 轮 | 3.009s | OK |
| B1 | 4096 | thr4096 第 1 轮（交错对照） | 3.625s | OK |
| A2 | 2048 | thr2048 第 2 轮 | 3.032s | OK |
| B2 | 4096 | thr4096 第 2 轮（交错对照） | 3.081s | OK |

- **序列**：A1(2048) → B1(4096) → A2(2048) → B2(4096)；每臂独立冷启动（~8.5 min），停止后再起下一臂，消除时间漂移与进程模式混杂。
- **每臂测量**：模式探针（2×8.2K + 1×32.8K）→ PR 四档（3 轮中位，唯一 nonce，max_tokens=1，pt/TTFT）→ DE C1/C12（4 轮中位，de_bench 口径：tput_sum + tokens/step + step_eff + acc/draft + ms/step 派生）→ 并发 C6/C12（3 轮中位，4K 档聚合吞吐）。
- **形态保真**：克隆脚本由生产 start 脚本 sed 生成，diff 保真门仅允许三类差异——容器名（tp4-bench-rank*）/ 镜像 tag（→LuZ0.3.1-bench-20260823）/ threshold（4096→2048）；`check_vllm_script.sh` 四机 PASS（checker 不校验 threshold 值，2048 不触发 FAIL）。**W4A4=2 / SHARED=1 / FI 0.6.16 / util 0.82 / batched 4096 / dspark n=7 逐字保留**（启动核验全命中）。
- **对照锚点**：luz031-deployment 2026-08-23 采纳带（PR 2950.5/2943.6/2834.2/2550.0；C6/C12 3057/3056；DE step_eff 18.2/80.2）。

## 3. 归因分析（接受率与步时分解）

### 3.1 PR 恶化归因（步数 + M_e）

8.2K 档 chunk 拆分（实测步时推算）：

| threshold | 8.2K 步数 | 每步时 | per-token | M_e（=chunk×6/256） |
|---|---|---|---|---|
| 2048 | 5 步（4×2048+尾） | ~586ms | ~357μs | 48 |
| 4096 | 3 步（2×4096+尾） | ~917ms | ~335μs | 96 |

- **步数 5 vs 3**：每步固定开销（TP4 all-reduce ~127ms/步、MoE 权重读 805MB/层×43、attention launch）多重复 2 步。
- **M_e 48 vs 96**：B12X @M_e=48 带宽效率低于 M_e=96 高效率区间（pr-de-bottleneck Roofline：吃满 bf16 TC 需 M_e≥114，4096 已接近、2048 更远）。
- 与 threshold-retest 2026-08-22 剂量-反应（1024<2048<4096，per-token 388→388→351μs）同族；本窗 thr4096 per-token 335μs 与其快模式一致。

### 3.2 DE 归因（接受率 vs 步时）

- **步时持平**：C1 52.9 vs 53.3ms（+0.8%）、C12 12.0 vs 12.1ms（+0.8%）——decode 步时长与 threshold 无关（decode 每步 M 由并发填充，不随单请求 chunk 粒度变）。
- **接受率运气**：thr2048 双臂 tokens/step C1 4.81 / C12 4.25 低于 thr4096（5.23/4.49），属 probabilistic 采样接受率轮间波动（acc/draft 2.8-5.0 区间内），与 threshold 无机制关联。
- **step_eff 归一结论**：接受率归一后 -1.1%/-1.3% → 持平 → **threshold 不影响 decode**。

## 4. Threshold 2048 判决

| 维度 | 判定 | Δ（thr2048 vs thr4096） |
|---|---|---|
| PR 单流 prefill | 🔴 **恶化** | -2.8% ~ -5.8%（全档，超 ±3% 门） |
| DE step_eff（接受率归一） | ⚪ 持平 | -1.1% / -1.3% |
| DE 步时 ms/step | ⚪ 持平 | +0.8% |
| 并发 C6/C12 | ⚪ 持平 | -0.2% / -0.3% |

**结论：threshold 2048 不采纳，维持生产 thr4096。**
依据：PR 单流全面回退且超采纳门；DE/并发无收益；剂量-反应单调（1024<2048<4096）与 2026-08-22 threshold-retest 一致；2048 无独立优势（"要么不改、改则一步到 4096"的既有裁决维持成立）。
