## 三、仪器时间线与归因

### 3.1 三重仪器全部干净

| 仪器 | 覆盖 | 结果 |
|---|---|---|
| JIT 时间戳（jit_monitor + B12X_PRINT_COMPILE_PROGRESS=1） | 8 臂全部 bench 窗口 | **零事件**（无 Triton/b12x 推理期编译告警）→ 候选④（形状 JIT）对本次慢轮**排除** |
| RDMA 错误计数（discard/constraint/rcv_errors × 4 口） | 全部 64+ 轮 | **零增量** → 候选②残余（拥塞/重传）**彻底排除** |
| RDMA 流量（每 8.2K 轮 xmit 总量） | 全部轮次 | 7.7-9.0GB，**与快慢无关**（B2 慢轮 8944MB vs 快轮 7935-8891MB；A3 慢轮 8981 vs 快轮 7935）→ 慢轮不做额外通信；第 1 对观察到的"2048 +10% 流量"经全矩阵验证为采样窗口噪声（A3/B3/C1 流量区间完全重叠） |
| dmon SM/功率（节点 01+02，1s） | B1/B2 慢轮窗口 | **双节点 SM 持续 90-96%、功率 57-62W，无静默期**（仅轮间正常空闲）→ host 侧停顿排除；慢轮期间 GPU"全忙但更慢" |

### 3.2 决策树走线（§1.5 P5）

```
慢轮存在？是（A 臂 2/15、B 臂 4/15、C 臂 0/10，4K 档急性 <2200）
├─ 与 JIT 时间戳相关？否（零事件）
├─ SM 静默期？否（01+02 双节点 96% 全程）
├─ RDMA 错误跳升？否（全零）
└─ → 叶节点：kernel 级/同步锁步慢化（需 torch profiler / NCCL trace 才能再往下钉）
```

**注意**：慢轮在 1024 臂同样出现（A2 r1 1813、A3 r3 1894）——**慢轮现象与 threshold 无关，是独立的间歇性系统现象**，不构成对扩 M 的阻塞。

### 3.3 新发现：重启级"模式"方差（昨日混杂的真身）

- **臂内轮间高度一致，臂间整体漂移**：A1 五轮 2526-2551（CV<1%）、B3 五轮 2664-2679、C 两臂 2784-2862；但 A1/A2/A3 臂中位 2546→2369→2420，B1/B2/B3 2576→2568→2674——**进程重启后整体落入快/中/慢模式，模式与 threshold 无关（两配置都访问全模式）**
- **warmup 即探针**：首个真实 prefill 的 TTFT 与本臂模式强相关——warmup ≤3.2s → 快模式臂（A1/B3/C1/C2）；warmup ≥4.3s → 中/慢模式臂（A2/A3/B1/B2）。模式在进程首个 prefill 前已确定
- **机制候选（实证线索）**：EngineCore 进程按设计钉在 CPU 15-19 核，但**该核区并非内核隔离**——containerd/containerd-shim/dcgm-exporter/alertmanager/cupsd/dashboard-admin 等宿主任务同核驻留与瞬时竞争（13:25 实测）。重启时刻的核竞争状态差异 → 进程模式差异，与 pr-de 报告 E2（aicad CPU 竞争 -4%）同族但幅度更大
- **昨日 A/B 完美解释**：rollback 臂（05:59，10× warmup 后仍慢）落在慢模式、armA（06:47）快模式、armB（07:00）中模式带双峰轮——26 个百分点的"同配置反差"与 ±8-13% 臂间模式方差 + 慢轮叠加完全吻合

### 3.4 4096 档为何无慢轮（观察，非定论）

C1/C2 两臂共 10+6 轮全部紧凑（4K CV<1%），且 warmup 即快。两种解释：① 快模式运气（2/2 臂）；② M=4096 与 budget=4096 相等时调度路径更简单（每请求整段占满 budget，无 chunk 尾块拼接）。样本不足以区分，如实标注。

## 四、归因裁决与扩 M 路线建议

### 4.1 裁决：**A——昨日 -22.5% = 实验混杂**

| 昨日结论 | 复测证据 | 裁决 |
|---|---|---|
| "2048 使 PR 4K -22.5%" | 3/3 配对中位 +1.2%~+10.5%，合并 +6.4% | **推翻**：系重启级模式方差 + 慢轮叠加的混杂 |
| "2048 臂双峰" | 双峰复现但 1024 臂也有慢轮（2/15），且仪器全干净 | 部分保留：慢轮是真实系统现象，但与 threshold 无关 |
| "步时比 2.06-2.17× > 2.0 ⇒ 小额真实回归" | 快轮步时比仅 1.58×（per-token -1%），慢轮口径 2.04× 由慢轮现象贡献 | **修正**：2048 快轮无回归；+3-8% "回归"是慢轮/模式污染 |
| DE 不受影响 | （本窗未重测 DE；昨日两臂 DE 归一持平） | 维持 |

### 4.2 扩 M 路线裁决：**重开，且直接跳到 4096**

1. **threshold=4096（= max-num-batched-tokens，当前上限）是最优剂量点**：+12% PR（单流口径）、双臂稳健、零慢轮、剂量-反应单调。M_e=96 进入 B12X 高效率区间，W4A4/merged 等"算力利用"子路线的 M 前提闸门打开
2. **生产变更建议（需人类工程负责人复核后择窗执行）**：`--long-prefill-token-threshold 1024 → 4096`（四机同步：01 head:57 + 02/03/04 worker:56）。预期 PR 四档整体 +10-13%；DE 昨日已证 threshold 无关。变更后建议 DE C1/C12 复测一轮 + 多日监控
3. **继续上探需先抬 budget**：M > 4096 需 `--max-num-batched-tokens` 联动（激活峰值/KV 预算会变，属独立实验，勿与 threshold 变更混做）
4. **未采纳 2048 作为推荐值**：无独立优势（介于两者之间），既然要改，一步到 4096

### 4.3 新开问题（移交后续窗口）

- **P1-新：重启级模式方差（±8-13%）**——所有 A/B 实验的隐性杀手。方法论强制：交错设计 + warmup 首请求作模式探针（TTFT >4s 的臂数据降权）。机制候选：CPU 15-19 核宿主任务竞争；建议下窗口 torch profiler + NCCL trace 钉慢轮与模式根因
- 慢轮（急性 -23%~-45%）机制未定：仪器无信号、GPU 全忙、同流量零错误——锁步慢化，需 profiler
- 02 节点遗留陈旧 head 脚本副本（n=5，不在执行路径，未动）建议择机清理防误用
