## 1. tuner 兼容（≤40KB→LL / >40KB→Simple）

- **机制**：生产 env `NCCL_TUNER_THRESHOLD=40960`（40KB 阈值）驱动协议路由；tuner 插件 `libnccl_tuner_persize.so` 仅用于 bench（容器 env 无 NCCL_TUNER_PLUGIN）
- **A/B 窗口 B1 实测**（`/tmp/nccl-abB-B1/latency.txt`，同当前生产 4ch 配置）：
  | 消息    | B1(4ch) out-of-place | 判定                              |
  | ----- | -------------------- | ------------------------------- |
  | 14KB  | 43.23µs              | ✅ LL 域（≤40KB→LL 未被 4ch 破坏）      |
  | 112KB | 82.69µs              | ✅ Simple+4ch（>40KB→Simple 路由正常） |
  | 224KB | 86.10µs              | ✅ Simple+4ch 稳定                 |
- **窗口复测（2026-08-17 13:5x，vLLM 停机后 GPU 纯净）**：
  | 消息    | B1 复测 oop/ip (µs) | A/B 窗口 B1 (µs) | 判定                         |
  | ----- | ----------------- | -------------- | -------------------------- |
  | 14KB  | 46.81 / 42.98     | 43.23 / 41.31  | ✅ LL 域（≤40KB→LL 未被 4ch 破坏） |
  | 112KB | 88.77 / 85.18     | 82.69 / 81.13  | ✅ Simple+4ch 路由正常          |
  | 224KB | 93.44 / 87.13     | 86.10 / 85.60  | ✅ Simple+4ch 稳定            |
- **判读**：复测数值较 A/B 高 3-7µs（停机后立即测，GPU boost 未满 + 运行波动），但**量级与趋势完全一致**：14KB 位于 LL 路由、112/224KB 走 Simple+4ch（远低于 B0 16ch 的 126/160µs），**tuner 阈值路由与 4ch 无冲突，协议选择未被破坏**

## 2. libncclpin 兼容（绑核）

- **容器 LD_PRELOAD 链**：`LD_PRELOAD=/opt/libncclpin.so /opt/nccl-ringonly/libnccl.so.2`，四机容器 inspect 一致；lib 以 ro 挂载 `/opt/libncclpin.so`
- **运行进程实证**（/proc maps，需 sudo）：四机 vllm 进程均映射 libncclpin（4 处）+ libnccl.so（8 处）→ **preload 生效**
- **绑核日志**：`[libncclpin] default => CPU 5-19`、`[Proxy Progress] Device 0 CPU core 13/19`（A/B nccl 日志）→ 线程绑核生效
- **结论**：4ch 仅影响通道数，不涉及线程绑核路径，libncclpin 兼容 ✅

## 5. 368KB 复测（遗留项，✅ 窗口已实测）

- **背景**：A/B 窗口 run_lat.sh `-b 14K -e 368K -f 2` 实际扫到 224KB（458752>368K 截断），**368KB 单点原未实测**；报告外推 120-130µs
- **窗口实测（2026-08-17，B1 4ch，vLLM 停机 GPU 纯净）**：


  | 指标                 | 实测           | 外推        |
  | ------------------ | ------------ | --------- |
  | 368KB out-of-place | **103.46µs** | 120-130µs |
  | 368KB in-place     | **99.75µs**  | —         |
- **判读**：**实测显著优于外推（-17~23%）**，368KB 在 4ch 下仅 ~100-103µs，与 Simple+4ch 收益曲线一致（112KB=83→368KB=100，随尺寸平缓增长），无 LL 爆炸、无异常拐点。NCCL 日志确认 **4 coll channels** + RING-ONLY v4
- **对 v2.0 定版的意义**：368KB 不再是瓶颈顾虑——B1 在 decode 主消息带（14-112KB）与大消息（224-368KB）均净收益，端到端已由 Tessa 基准证实
