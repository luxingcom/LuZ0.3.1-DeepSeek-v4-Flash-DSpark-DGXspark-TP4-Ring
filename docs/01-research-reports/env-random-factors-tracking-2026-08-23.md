| 问题 | 结论 | 证据强度 |
|---|---|---|
| **a) 环境级随机因素清单** | 四类：①接受率随机性（probabilistic draft 采样，轮内）；②重启级模式方差（重启落点，跨 session）；③AR stall（单节点单核约束，per-run 抽签）；④轮内干扰（守护进程/embedding 共租/API 路径软中断） | ①②③【实测】，④【实测旁证/推断】 |

## 1. 环境级随机因素清单与机制（因果链展开）

### 1.1 因素 A：接受率随机性（probabilistic draft 采样，轮内主方差源）

**机制链**：
```
probabilistic draft 采样（temp>0 语义，n=7）
  → 每轮 draft 提议序列不同 → 每轮接受长度（acc_len）轮间大幅波动
  → de C1 轮 tput 方差 36.6% 完全由接受率解释，steps/s 恒定 19.6-20.1
  → 单流 decode t/s = acc_len × steps/s → t/s 轮间双峰
```

**证据**：
- 【实测】slowround 阶段2：de C1 轮间 tput 方差 36.6%，同 prompt 下 steps/s 恒定 19.6-20.1（**基础设施无退化**）。
- 【实测】Session A S1 10 轮原始序列：`72.6/71.9/131.1/65.2/110.1/110.2/66.9/83.3/81.4/74.3` → 强双峰（7 低带 65-85 / 3 高带 110-131）；低带 ≈ acc_len 3.7-4.3、高带 ≈ 5.5-6.7，steps/s 恒定。
- 【实测旁证】w4a4-ext B2 质量门：同配置背靠背自比 reason/zh prompt DIFF——probabilistic 投机解码运行级非确定性实锤（与 W4A4 无关）。
- 【推断】probabilistic 采样语义与 mtp-tuning 的 temp-0 下 probabilistic=greedy 一致；官方 8/19 分布对称（σ 小）暗示官方可能用 greedy 或更紧采样，接受率方差小于我们。

**性质**：环境/负载固有，W4A4 无接受率机制（同 n7 下 step_eff 中性）。**n5→n7 的放大效应**：n7 提高接受率均值（+11.9~18.6%），同时接受长度方差上限随 n 增大（未定论，T4 待校准）。

### 1.2 因素 B：重启级模式方差（重启落点抽签，跨 session 均值偏移）

**机制链**：
```
TP4 重启 → communicator 建立期抽签（pin 落点 / channel→NIC 映射 / 资源分配）
  → 本臂"模式"（快/中/慢，warmup 首 prefill TTFT 差 ~40%，稳态 PR 差 ~3.4%）
  → 模式按重启落点固定，session 内不可观测（单次重启单模式）
  → 跨 session 对比时表现为系统性偏移
```

**证据**：
- 【实测】expd-r123：7 次抽签首请求 TTFT 双簇（慢 4.25-4.43s ×4 / 中 3.07-3.48s ×3），稳态 panorama PR 慢臂 2753-2768 vs 中臂 2832-2853（差 ~3.4%）；R1-R3 卫生修复后模式方差仍在（R7 又落慢臂）。
- 【实测】H2（libncclpin 按名 pin 漏网）4/7 轮实锤（NCCL IbAsync 漏 pin / EngineCor 落点越界），**但与臂模式不相关**（慢臂 2/4 有越界、中臂 2/3 有越界）→ H2 不是模式方差主因。
- 【推断】剩余头号候选 = NCCL channel→NIC 口映射抽签（环网 2 收 2 发）+ 其他重启期资源分配（expD 建议下一窗口实验 C 定论）。
- 【实测旁证】bench-regression-attribution：08-21 W4A16 同项中位 92.8（均值 90.3，偏度小）vs 本次 77.8 —— 跨 session 不稳定 + 接受率随机性共同作用。

**性质**：环境固有。**对 Session A 的具体影响**：Session A 为单次重启单模式，若抽中慢簇，则整 session 稳态 PR 比快簇低 ~3.4%——这是跨 session 均值偏移的一部分，不解释轮内双峰。

### 1.3 因素 C：AR stall（单节点单核约束，per-run 抽签）

**机制链**：
```
GB10 平台 GDR=0（cuMemGdrSupport 0，四节点实锤）
  → AR 数据面 = NCCL proxy 线程 host staging（C2C+ibverbs），依赖 proxy 活性
  → ≥1 节点 worker 进程被压到单核（CPU 8/9 = 该节点 NCCL proxy 目标核）[12/12 完美相关]
  → 该核饱和 → proxy 等价线程无法 busy-spin，转入 timed-poll（wake ~18-28ms ≈ AR stall 时间）
  → 该节点 ring 数据流阻塞 ~18ms → 整组 4 节点 ring allreduce 全局 STALL
  → rank0 计时 17.99-21.18ms（CLEAN 臂 0.586-0.600ms），1ms 量子化
```

**证据**：
- 【实测】expverdict：E1 系列 stall 6/10（60%），med 17.99-21.18ms；单核约束矩阵 12/12 完美相关（每个 STALL run ≥1 节点受限，受限节点随机）。
- 【实测】envstall：GDR=0 实锤；stall 运行 proxy 核 ~0.9-1.3kHz arch_timer（1ms 量子互证）；RC1（hrtimer_nanosleep+~1kHz）按字面未实证，timed-poll 是单核约束下游症状；实验 C 排除 channel→NIC 映射。
- 【实测旁证】生产稳态未观测到灾难性 stall：expD R1-R7 panorama 全带内（若 17ms/AR 作用于 prefill 86 次 AR，PR 将坍塌 >30%，未观测）。
- 【推断】形态差异：nccl-tests 每运行新建/销毁 communicator（抽签 ~60 次/日）vs 生产长寿命 + CUDA graph 高频唤醒（可能免疫）。**对 Session A bench 的影响是潜在风险而非已证主因**。

**性质**：环境固有（cgroup cpuset 瞬时收窄 vs 调度器挤占未闭环，E3 定向）。生产 vLLM 形态是否中招需 E5 判决。

### 1.4 因素 D：轮内干扰（守护进程 / embedding 共租 / API 路径软中断）

**机制链**：
```
dockerd/containerd/dcgm-exporter/postgres/docker-proxy 无 pin 游走（15-19/5-9 带）
  + 03/04 embedding 共租（无 pin 线程侵入 5-19）
  + API path veth 软中断集中 CPU13（A725 慢核）
  → 间歇活动（scrape/docker pull 解压/embedding 请求）撞关键核 → 轮内慢轮
  → 诊断口径：同 prompt 下 steps/s 掉档（非 tput）
```

**证据**：
- 【实测】slowround 阶段1：守护进程无 pin 全景（dockerd 56-58 线程大量落 15-19；containerd/dcgm 同带）；embedding 无 pin 游走 PSR 1,2,4,5,6,12,15,17。
- 【实测】快模式臂 0 慢轮（stability 14 轮全部稳定，守护进程平静）→ 慢轮需要干扰事件触发。
- 【实测旁证】01 当日 `docker pull eugr/spark-vllm-b12x` 运行中（containerd/dockerd 无 pin）——fi-eugr-prep 与基准同期的干扰源实录。
- 【推断】R1-R3 卫生修复（IRQ 迁离 8-9 / 守护进程限带 / embedding pin）已落地，降低此类干扰概率；但 15-19 带 EngineCore 与残留无 pin 线程仍存在结构性竞争。

**性质**：环境固有；修复后概率降低但未根治（R4 libncclpin v9 为根治项，降级卫生）。

## 2. 哪些是 W4A4 改动放大/引入，哪些环境固有

| 因素 | W4A4 是否引入/放大 | 机制 | 证据 |
|---|---|---|---|
| **接受率随机性** | **不引入**（W4A4 无接受率机制）；**n5→n7 间接放大**（接受长度方差上限可能随 n 增大，未定论） | W4A4 只改权重/激活量化，不改 draft 提议/验证语义；同 n7 下 step_eff 中性 | 【实测】w4a4-ext B1 vs B2 step_eff C1 +3.4%/C12 -2.4%（噪声带内）【推断】n 方差上限 |
| **重启级模式方差** | **环境固有**（R1-R3 修复后仍现，R7 慢臂） | libncclpin pin 竞态（H2）实锤但非主因；channel→NIC 映射抽签为剩余头号候选（实验 C 待定） | 【实测】expd-r123；【推断】机制归属 |
| **AR stall** | **环境固有**（GB10 GDR=0 + 单核约束，与 NCCL 逻辑无关） | nccl-tests 形态特有概率高；生产稳态未见灾难 stall | 【实测】expverdict/envstall；【实测旁证】expD panorama |
| **轮内干扰** | **环境固有**（守护进程/embedding/API 路径） | 间歇活动撞关键核；修复后概率降低 | 【实测】slowround 阶段1；【推断】修复后残余 |
| **C12 步时代价（F2）** | **W4A4 引入（已知代价）** | W4A4 full decode 已知 -6~-9%（phase3b）；luz031-deployment DE C12 -8.0%；w4a4-ext 同日 ±3%（两口径并存） | 【实测】luz031-deployment；【实测旁证】phase3b |
| **并发平均效应** | **W4A4/形态间接改变可见度** | C12 并发跨流平均抹平接受率方差 + W4A4 prefill 增益 + n7 接受率优势盖过 C12 decode -8% → C12 +1.9% | 【实测】bench-regression §2.3 |

**结论**：W4A4 改动**不引入新的环境级随机源**。它对"不稳定波动"的作用是**间接/可见度层**——① C12 decode 步时 -8% 进入代价带，使低接受率轮次在并发下更难被顺风盖住；② n5→n7 在提高接受率均值的同时，接受长度方差的尾部可能变宽（T4 待校准）。**不稳定波动的主机制全部来自环境固有因素**。

## 3. 定量贡献与交互

### 3.1 C1 单流中位 -23.9% 的分解（相对官方 8/19，n5/W4A16）

| 因素 | 估计贡献 | 依据 | 强度 | 是否本次引入 |
|---|---|---|---|---|
| **接受率随机性（F4a）** | **-10% 纯偏度损失**（中位 77.8 vs 均值 86.7）；低接受率轮次占比/深度高于 08-21 | §1.1 双峰分布 + slowround steps/s 恒定 | 【实测+推断】 | 部分（Session A 更双峰） |
| **重启级模式方差（F4b）** | **跨 session 均值偏移的一部分**（08-21 92.8 → 本次 77.8；模式差 ~3.4%） | expd-r123 双簇 + bench-regression §2.4 | 【实测】 | 否（环境固有） |

| **合计** | **C1 中位 -23.9%**（最优 +10.1%） | Session A | — | — |

### 3.2 交互效应

1. **接受率随机性 × 并发度（主交互，已实证）**：并发平均效应随并发度单调增强——C1 -23.9% > C4 -14.4% > C8 -4.1% > C12 +1.9%（bench-regression §2.3，趋势一致性）。**单流完全暴露接受率方差，并发跨流抹平**。这是"低并发中位回退 vs 高并发提升"的核心解释。
2. **重启级模式方差 × AR stall（潜在叠加）**：若某 session 抽中慢簇（warmup TTFT +40%）且生产形态恰遇单核约束（E5 未判），两者叠加可使中位进一步下探。当前证据：生产稳态 panorama 全带内 → 叠加未证。【推断】
3. **接受率随机性 × 模式方差（跨 session 与轮内的混合）**：模式方差解释跨 session 均值偏移（慢簇稳态 PR 低 ~3.4%）；接受率随机性解释 session 内轮间方差（36.6%）。两者独立正交，共同作用使"单次 session 单次重启 + 10 轮"的测量最不稳定——**这正是重测协议需要解决的窗口**。
4. **probabilistic 采样 × greedy 质量门（测量侧假阳性交互）**：probabilistic 投机解码运行级非确定性导致朴素逐字比对假阳性（w4a4-ext B2 初判 4/6 MATCH 触发；thr4096 verify greedy FAIL 后被裁定假阳性）。**质量门必须用稳定 prompt 集或 KL 散度**。

### 3.3 定量口径（C1 单流）

```
C1 中位 77.8（10 轮，双峰）
  ├─ 均值 86.7 → 中位-均值差 = -10% 纯偏度（接受率随机性）
  ├─ 最优 131.1 → 能力上限 +5.7% vs 官方（未退化，n7+W4A4 顺风兑现）
  ├─ 08-21 同项中位 92.8 → 跨 session 偏移 ~-16%（模式方差 + 接受率随机性共同）
  └─ 官方 97.1 → 官方 draft 质量 + 步时/env 既有差距（非本次引入）
```

## 4. 可操作建议

### 4.1 重测协议升级（最高优先，零窗口成本）

| # | 措施 | 依据 | 收益 |
|---|---|---|---|
| P1 | **单流轮数 10→30** | 当前 10 轮双峰下中位不稳定（中位 77.8 为单点抽签结果） | 中位置信度提升（30 轮下双峰比例更稳健） |
| P2 | **报告同时给"中位/均值/最优/低接受率轮占比"**，不再单用中位 | 中位-均值差 = 接受率随机性的直接度量 | 客观呈现分布形态 |
| P3 | **慢轮判定看 steps/s 非 tput** | slowround 阶段2：tput 方差可能只是 MTP 接受率；steps/s 变化才是基础设施问题 | 消除接受率假阳性慢轮 |
| P4 | **跨 session 对比用交错 A/B（同窗跑 W4A16/W4A4 各一轮）** | 模式方差按重启落点固定，跨 session 对比受模式污染 | 消除模式方差对对比的污染 |
| P5 | **质量门改用稳定 prompt 集（fox_repeat/count/code/list 4/4）或 KL 散度** | reason/zh prompt 运行级不稳定（probabilistic 非确定性） | 消除朴素逐字比对假阳性（thr4096/w4a4-ext 已两次触发） |

### 4.2 测量侧 vs 环境侧治理（E3/E5 衔接）

| 侧 | 治理项 | 状态/动作 | 归属 |
|---|---|---|---|
| **测量侧** | 重测协议 P1-P5 | 建议立即采纳（零窗口成本） | 架构/QA |
| **环境侧-AR stall** | **E5：对当前生产跑 panorama 3 轮**（闭环 A2） | 待窗口执行（4K prompt，TTFT/PR 带内 → 生产未中招） | SRE |
| **环境侧-AR stall** | **E3：单核约束触发机制定位**（cgroup cpuset 瞬时收窄 vs 调度器挤占） | 待窗口执行；若 cgroup 层原因可低成本规避 | SRE |
| **环境侧-模式方差** | **实验 C：NCCL channel→NIC 映射取证**（NCCL_DEBUG=INFO 通道建立日志 × 臂模式 × RDMA 分口流量） | 待窗口执行（模式方差判决） | SRE |
| **环境侧-卫生项** | R1（IRQ 迁离 8-9）/ R2（守护进程限带）/ R3（embedding pin） | **已落地并持久化**（expd-r123）；维持 | SRE |
| **环境侧-根治项** | R4（libncclpin v9 修 pin 竞态） | 降级为卫生修复项按需排期（H2 与模式不相关） | kernel 工程 |
| **环境侧-本底** | R5（nohz_full=8-9 消除 arch_timer 常驻） | 低优先级（实验 A 后评估，需重启验证） | SRE |

### 4.3 隔离核调整 / 调度参数

- **已落地的**：mlx5 IRQ affinity 5-9 → 0-4,10-14（隔离核 8-9 不再吃 NIC 中断）；containerd/dockerd/dcgm/node-exporter AllowedCPUs=0-4,10-14；03/04 embedding cpuset=0-4,10-14。**维持**，不主动回滚。
- **不建议现在做的**：nohz_full=8-9（需重启 + rcu_nocbs 交互验证，收益 ~375-725Hz/核本底噪声的量级，排实验 A 后）；threshold 回退 8192（已双重证伪：性能无增益 + KV 塌缩 -36.7%）。
- **可评估的**：probabilistic vs greedy draft 采样 A/B（T4 校准项）——若 greedy 臂方差收窄且接受率均值可接受，中位可回升（需 mtp-tuning 延伸窗口）。

### 4.4 对 lm_head FP8 / 性能释放的影响

- lm_head FP8 属 **F2（步时）修复**，只解决"C12 步时 -8%（W4A4 代价）"与 prefill GEMM 效率，**不解决 F4 不稳定**。对 Session A 低并发/Agent 中位回退的理论改善仅 ~1.4%（C1 步时口径，详见 lmhead-fp8-project 报告 §2.3）。
- **排程含义**：不稳定治理（重测协议 + E3/E5）与 lm_head FP8 立项**正交**，可并行；但**判定 lm_head FP8 是否生效的 A/B 窗口必须先采纳重测协议 P1-P5**，否则测量噪声（±8-13% 模式方差 + 接受率随机性）将淹没 ~5% 量级的步时收益。
