## 任务 2：Grafana 预填充速度 8000 核实（主理人实测 + Tessa 判定）

### 决定性证据（counter 增量分析）

| 时间粒度 | prefill rate | 说明 |
|---------|-------------|------|
| **15s 窗口** | **7738~7757 t/s** | 每 15s 采样间隔恰好 +116,000 tokens（131072 长 ctx prefill 请求完成瞬间） |
| 60s 窗口 | 1935 t/s | 稳态聚合 |
| 5m 窗口 | ~2000 t/s | 24h 峰值仅 2073 t/s |
| 30s 细粒度 2h | 峰值 2212 t/s | 从未 >3000 |

### 结论：8000 t/s 是短窗口计数毛刺（Tessa 修正版），真实稳态 ≈1935 t/s

1. **关键判据**：15s 桶 = 7738 与 60s 聚合 = 1935 **并存** ⇒ 增量模式是"每 ~60-75s 一次 +116K"（每个 131072 请求完成时 counter 一次性 +116K，落在哪个 15s 桶哪个桶就显示 116K/15s≈7738）。若真是持续 7738 t/s，60s 聚合必然也是 7738，不会只有 1935
2. **真实稳态 prefill ≈1935 t/s，与 benchmark 900~2000 完全吻合**——benchmark 口径被验证正确
3. **物理佐证**：131K 长 ctx prefill 是 attention/内存带宽受限，单请求 7738 t/s 不现实（那是短 prompt 批量峰值）；1935 t/s 才是长序列合理值（GB10 理论 1.5万 t/s 是 matmul 峰值，长 ctx 到不了）
4. **非 cached 虚高、非多机叠加**：counter 增量是真实 prefill tokens
