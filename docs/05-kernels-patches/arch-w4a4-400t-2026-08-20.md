# ARCH — W4A4 路线A 400 TFLOPS 达标性核对报告

> **架构师**：阿奇（system architect） | **日期**：2026-08-20
> **范围**：DGX Spark GB10 / sm_121a / Triton 3.6.0 / vLLM 0.26 / 镜像 dspark-vllm-gx10:0.2.1-v026.0
> **方法**：只读研究 + 静态代码/SASS 符号核对（未动生产容器、未跑重型 benchmark）。性能实测由 sre-engineer 并行产出，本报告引用上轮 bench_big/bench_mmaf_final 实测（60~187 TFLOPS）与官方规格。
> **问题**：W4A4 下路线A 是否可达 400 TFLOPS？（用户已裁定 W4W4 硬指标 400T；W4A8 的 187T 已达标）

---

## 0. 结论速览（TL;DR）

| 维度 | 判定 |
|---|---|
| **技术路线 = W4A4 原生 FP4 MMA** | ✅ 成立（e2m1 4-bit 权重 + e2m1 4-bit 激活，原生 SM120 mma，**非 bf16 模拟**） |
| **400 TFLOPS 数值指标** | ❌ **在 GB10 上不现实**（400 = 500T 稠密 FP4 峰值的 80%，超出当前实现可达上限；优化后贴近的上限约 300~350T） |
| **替代建议** | ① 将硬指标下调到 **280~330T**（配合下述优化清单可行）；② 或接受既有 **W4A8 187T** 作为已达标档；③ 400T 仅当**换更高算力硬件**（B200/GB200）才成立 |

**一句话**：技术上路线A 确实是规范的 W4A4 原生低精度路径（这部分✅，应保留）；但 **400T 这个数本身**建立在「GB10 稠密 FP4 峰值≈500T × 80% 效率」的假设上，而 Blackwell 在生产 GEMM 上通常只能到 55~75% 峰值，因此 **"400T" 作为硬指标在 GB10 上需改判，需下调或换硬件**。

---

## 1. 技术路线核对：路线A 是否真走 W4A4（e2m1×e2m1）

### 1.1 判定：✅ 是，规范的 4-bit 权重 + 4-bit 激活，非 bf16 模拟

路线A 适配层 `nvfp4_4w4a_mmaf.py` 的核心调用链：

```python
# __call__ 内：
a_q, a_sf = _co.scaled_fp4_quant(A.float().half(), gs, is_sf_swizzled_layout=True, backend='none')   # 激活 → e2m1 FP4
out = _co.cutlass_scaled_fp4_mm(a_q, self._wq, a_sf, self._wsf, alpha, torch.bfloat16)
# self._wq (preprocess_weights) 也是 scaled_fp4_quant(W_fp32.half(), ...) → e2m1 FP4 权重
```

**证据链（叠加式）**：
1. **输入 dtype**：A 激活经 `scaled_fp4_quant` 量化为 e2m1 FP4（4-bit）数据 + 块 scale；权重同样。→ 输入两侧均为 **4-bit**，符合 W4A4 定义。
2. **数值精确对齐**：`bench_mmaf_final` 8/8 shape 与 vLLM 官方 `dequantize_to_dtype` **rel=0.00141**。若退化为 bf16 模拟，rel 会显著更大（对照 v15 bf16 适配层 rel 明显偏离，且纯 bf16 GEMM rel≈1e-2 级）。rel=0.00141 该量级只能由同精度原生 FP4 MMA 产生。
3. **性能远超 bf16 上限**：实测峰值 **187 TFLOPS** ≫ GB10 bf16 稠密上限（官方规格 ~100~125 TFLOPS，见下）。算术上不可能由 bf16 路径达到。
4. **符号/架构证据**：
   - `_C_stable_libtorch.abi3.so` 内嵌 **sm_120 cubin** 及 1349 个 FP4 符号（`cutlass_scaled_fp4_mm`、`scaled_fp4_quant`、`torch_dtype_float4_e2m1fn_x2`、`e2m1`）。
   - vLLM 官方 `cutlass_scaled_fp4_mm` / `scaled_fp4_quant` 定义在 `csrc/quantization/fp4/nvfp4_scaled_mm_kernels.cu`，明确 FP4×FP4 或 FP4×FP8 GEMM，`FLOAT4_E2M1X2`（e2m1 打包），scale 为 e4m3。
5. **SASS 门禁口径**：SM12x 原生 FP4 应以 `mma.*e2m1` / `mmaf_scaled` 为准；**勿用 tcgen05**（SM10x）。上轮 `SASS_GREP_SUMMARY` 样本显示 `HMMA.16816.F32.BF16 / e2m1=0 / tcgen05=0`，但那是对旧 Triton v12 内核（fp32/bf16 路径）的 dump，**不是**路线A 的 CUTLASS FP4 内核——路线A 走的是 vLLM 预编译 CUTLASS cubin，证据是符号+性能+数值三重印证，而非该 .sass dump。**重要核对注意：文件中的 .sass/.ptx 属于旧 Triton 内核，不能用作路线A 的 SASS 门禁证据，应改用 cubin 符号层证 + GEMM-only 数值/性能佐证。**

### 1.2 一个需要向用户澄清的口径点

- 任务描述中"W4A4（e2m1 4-bit 权重 + e2m1/e4m3 4-bit 激活）"——路线A 的**激活**经 `scaled_fp4_quant` 也是 **e2m1**（4-bit），不是 e4m3。e2m1×e2m1 即 Blackwell 原生 FP4 MMA 最硬核形态。这是合规 4W4A，且比 W4A8 更激进（激活也压到 4-bit），正确性仍 8/8，说明量化在目标模型尺度可用。

## 2. 400T 差距归因（187 → 400 = 2.1×）

### 2.1 先锚定 GB10 硬件算力上界（决定性）

- 官方规格：GB10 "最高 1 PFLOP FP4（稀疏）"，Notes 明确 **"1 TOPS 理论 FP4 利用稀疏性特征"**。
- The Register / 多源实测口径：**"most you'll likely see from any GB10 systems is 500 dense TFLOPS at FP4"** → **稠密 FP4 峰值 ≈ 500 TFLOPS**（48 SM）。
- 因此 **400T = 500T × 80%**。这是判断的基石：**400T 要求 GEMM 打到稠密峰值的 80%。**

### 2.2 实测 187T 构成（哪里被吃掉）

`bench_mmaf_final`/`bench_big` 测量的是 `impl(A)` **整算子**，其中每次调用在 GEMM 前都会执行激活量化 `scaled_fp4_quant(A.float().half(), ...)`。即 **187T 包含激活量化 + FP16 往返转换 + workspace 分配的完整链路开销，非纯 GEMM**。README 明确：「性能含 A 量化（软件路径后端）+ workspace 分配；M 小时量化开销占比高」。

差距可拆为三段：
- **(a) 激活量化在关键路径**：`scaled_fp4_quant` 走 software backend（`backend='none'`），对 [M,K] 激活做 `float().half()` 转换 + e2m1 量化 + 块 scale；大 M/K 时占相当时间（大 shape 量化占比仍可观），纯 GEMM 应比整算子高。
- **(b) CUTLASS 内核未达 GB10 峰值**：即便 pure GEMM，CUTLASS FP4 内核在 GB10 48-SM / 273 GB/s 带宽 / 小 L2 下，通常只到峰值 55~70%（188→250~300T 级），**达不到 80%**。
- **(c) 无 CUDA Graph 融合**：`scaled_fp4_quant` + `cutlass_scaled_fp4_mm` 各自独立 launch、各自分配 workspace，launch 间隙与算子间数据往返未隐藏。

### 2.3 理论可达性数学

| 场景 | GEMM 效率假设 | 预计 TFLOPS |
|---|---|---|
| 现状整算子（含 A 量化） | —（实测） | **187**（12288 shape 峰值） |
| 纯 GEMM（去量化，估） | 峰值 50% | ~250 |
| 加 CUDA Graph + cutlass 量化融合 | 峰值 60~65% | **~300~330** |
| 全优化 + 理想 tile/autotune | 峰值 70~75%（Blackwell 生产现实上限） | **~350~375** |
| **400T 硬指标** | **需 80%** | ❌ 超 Blackwell 生产现实 |

> 结论：即便投入全部优化（CUDA Graph 融合、`scaled_fp4_quant` 改 cutlass/硬件 backend、大 shape autotune、去 FP16 往返、workspace 复用），**GB10 上贴近的现实天花板约 300~375T，400T（80% 峰值）非稳健可达**。

### 2.4 编译器/Triton 角色（澄清：不是主要瓶颈）

- 任务问是否需要 PR #42209 / Triton 3.7+。**对路线A 而言不需要**：路线A 本来就走 vLLM 预编译 CUTLASS cubin，**绕开了 Triton 3.6 无原生 FP4 codegen** 的限制。Triton 3.7 的 FP4 改进只影响想要用 Triton `tl.dot_scaled` 自写内核的路线（那是路线B/自研），对「提升 CUTLASS FP4 到 400T」**无助益**。
- 真正的杠杆是：(1) 激活量化从 software backend 换 **CUTLASS on-the-fly 量化**并融合进 GEMM；(2) **CUDA Graph 捕获**整条 量化→GEMM→bias 链；(3) 消除 `A.float().half()` 双转换；(4) workspace 预分配复用；(5) 大 shape 专属 autotune。

## 3. 结论判定

### ✅ 技术路线：W4A4 成立
路线A = e2m1 权重量化 + e2m1 激活量化 + CUTLASS 原生 FP4 MMA，数值对齐官方（rel=0.00141）、性能远超 bf16、符号层含 sm_120 FP4 cubin。**这部分正确，保留，非 bf16 模拟。**

### ❌ 数值指标：400T 在 GB10 上不成立（需换指标或换硬件）
400T = GB10 稠密 FP4 峰值(≈500T) 的 **80%**，超出 Blackwell 生产 GEMM 现实可达上限（约 70~75% → ~350T）。在 GB10 上这是**结构性不可达**，不是调优能补齐的。

### 🟠 有条件可达（替代方案）
把硬指标从 400T **下调到 280~330T**，配合 §4 优化清单，在**最大 shape（M≥4096，K/N≥8192）**下大概率可达且可验证。这是 GB10 上具备交付意义的真实性能档位。

## 4. 可行动优化清单（若目标下调到 330T，优先执行）

| # | 优化项 | 预期收益 | 工作量 | 说明 |
|---|---|---|---|---|
| O1 | **纯 GEMM-only 基准分离**：先量化缓存 A，再只 benchmark `cutlass_scaled_fp4_mm`，量化不计时 | 暴露真实 GEMM 基线上限（估 250~300T） | Low（改 bench） | 区分"量化开销" vs "GEMM 内核上限"，避免把量化浪费误判为内核天花板 |
| O2 | **CUDA Graph 捕获**：`scaled_fp4_quant → cutlass_scaled_fp4_mm → +bias` 整链图捕获，消除 launch 间隙与算子间往返 | +30~60% 相对整算子 | Med | 参考 vLLM 官方 bench `do_bench_cudagraph`；生产 prefill 大 M 下收益显著 |
| O3 | **激活量化改 CUTLASS/hardware backend**（`scaled_fp4_quant(..., backend='cutlass')` 或 on-the-fly 融合量化），从 software backend 升级 | 隐藏 A 量化到 GEMM prologue | Med-High | 需核对 vLLM 0.26 该 backend 在 sm_121a 的可用性与数值一致性（回归 8/8） |
| O4 | **消除 FP16 往返**：当前 `A.float().half()` 双转换浪费。若激活可预存 bf16/fp16 或直量化，省一次转换 | ~5~10% | Low | 与 O2 图捕获一并消除 |
| O5 | **workspace 预分配复用**：`cutlass_scaled_fp4_mm` 每次 alloc workspace；改为预分配复用 | ~3~8%（大 shape） | Low | 避免 hot path 分配抖动 |
| O6 | **大 shape autotune + 保留最优 tile 配置**（M 尽可能大、GROUP_M swizzle、BLOCK_N≥128） | 上探 300+ | Low-Med | 目标档 280~330T 的最后一公里 |

> 注：要 **400T** 这四项都做到极致也只到 ~350T，故 §3 判定不变。

## 5. 风险与权衡

| 风险/权衡 | 等级 | 说明 |
|---|---|---|
| **400T 硬指标在 GB10 结构性不可达** | 🔴 高 | 需用户重新裁定：降目标(280~330T) / 接受 W4A8 187T / 换高算力硬件。**不建议**以「PR/换 Triton」去硬追 400T（无效杠杆） |
| 路线A 依赖 vLLM 0.26 内置符号 | Med | 适配层独立 .py 可回退（删除即落回 v15）；记录 API 契约备将来升级核对 |
| 现有 .sass/.ptx 证据属旧 Triton 内核 | Med | 路线A 的 FP4 门禁应改用 **cubin 符号层** + GEMM-only 数值/性能三重佐证，勿用该 .sass dump 误判 |
| 优化(O3 backend)引入数值差异 | Med | 每项优化后必须回归 8/8 rel<0.02 |
| 目标 shape 依赖 | Low-Med | 400/330T 仅对超大 shape(M≥4096)成立；production prefill 若 M 小，性能显著下降，需与真实 batch 分布对齐预期 |

**权衡总结**：路线A 技术上已正确落地 W4A4 原生 FP4（✅）。性能硬指标的症结在**硬件上界**而非实现质量——400T 是 GB10 稠密峰值的 80%，生产不可达。**建议将 400T 改判为「GB10 上不可稳健达成的理论档」，采纳 280~330T + O1~O6 作为真实交付目标**；若用户坚持 400T，则结论为 ❌ 需换实现/换硬件（B200/GB200，其 FP4 稠密峰值上 1~2 PFLOP 级）。
