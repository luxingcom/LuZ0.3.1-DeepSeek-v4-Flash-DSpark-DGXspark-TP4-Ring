## 4. 层 3：模型层（>2× 的关键，风险最高）

### 4.1 反推：>2× 需要多少集中度？

设 MoE 占比 55%、非 MoE（注意力+其它）45%：
- 非 MoE 不动：2× 需 MoE **11×**——kernel 上限 3.3×（332T vs ~100T 现状），**不可能**
- 非 MoE 1.25×（调度/小优化）：需 MoE **3.9×** = kernel 3.3× × 覆盖效率 1.18 → **dense 层 merged 覆盖 ~100% 且全在 332T 档**
- 非 MoE 1.5×（含注意力优化）：需 MoE **2.75×** = kernel 3.3× × 覆盖 ~0.83 → **dense 层覆盖 ≥83%**

### 4.2 现状 vs 需求的差距

dense 层当前 merged 覆盖（M_g≥512）27%（M=8240）→ 需提升到 **83-100%（3-4× 集中度提升）**。

### 4.3 实现路径与代价

| 路径 | 做法 | 周期 | 风险 |
|---|---|---|---|
| **路由正则化微调**（主候选） | 训练时加 router 负载熵惩罚/组合稀疏正则 → 流量向少数组合集中；或蒸馏到"topk-热组合"路由 | 数周-数月（训练+eval） | **改变路由 = 改变模型行为——必须全量 eval（perplexity/基准/needle）验证质量；失败风险实质存在** |
| 推理时 logits 温度/偏置（免训练） | gate logits 加 sharpening 偏置 → 更集中但偏置选路 | 天级可测 | 模型质量风险同上（更粗暴）；效果上限低 |
| 专家数削减（256→64/128） | 重训或专家合并 | 月级 | 大手术；与 merged 覆盖正交（每桶专家更少 → 浪费更可控）；仅列选项 |

### 4.4 数据质量警示（层3 决策前置条件）

P1-1 路由数据的 top cohort（26.8% 单一组合、hash 与 dense 层同频 8220）**可能被合成 prompt 的重复结构高估**（filler 句式高度模板化 → 相同 token 大量重复 → 路由自然集中）。**层3 任何投入前必须用真实业务流量 prompt 重采集**（P1-1 采集器现成，B12xExperts.apply 挂钩复用）。若真实流量 dense 层集中度更低，层3 的 3-4× 提升目标更远。

## 5. 层 4：框架层（对 DSV4 结构性受限，低优先）

**源码核查结论**：fork 具备完整 `CompilationMode.VLLM_COMPILE`（piecewise + cache + shape 特化），**但对 `DeepseekV4ForCausalLM` 强制自动启用 `VLLM_USE_BREAKABLE_CUDAGRAPH=1` 并把 compile 置 NONE**（vllm/config/vllm.py:1180-1203——"model classes don't carry @support_torch_compile — breakable cudagraph is the supported PIECEWISE path"）。即：**DSV4 在本 fork 不走 torch.compile 是设计决定**（DSV4 自定义算子/DSL 调用会 graph break，compile 需模型侧适配工程）。
- 参考部署的 VLLM_COMPILE 增益大概率来自标准模型（Llama 系），对 DSV4 不直接可比。
- 若强行开启：需给 DSV4 模型类做 compile 适配（graph break 逐个修）——工程量大，且 compile 主要收益在 host 开销受限的 decode/小 batch，**prefill 是 GPU-bound，收益预期 ~5% 级**——投入产出差，列最低优先。
- 框架层更现实的项：异步调度已开 ✓、prefix caching 已开 ✓、`--enable-flashinfer-autotune` 已开 ✓——待 Task #25 差异表查漏。

## 6. 叠加算术与推荐序列

```
层1 配置(8240)          prefill ×1.15-1.25      [天级, 零风险]
× 层2 merged kernel     MoE ×1.5 → prefill ×1.35-1.5 (累计)  [1-2 周, 中风险]
× 层3 路由集中化        MoE ×2.2-3.3 → prefill ×1.6-2.1 (累计)  [数周-月, 高风险+质量门]
× 非 MoE 优化 1.25-1.5× (调度/注意力)             → ×2.0-2.6 (累计)
```

**推荐序列**：
1. **立即**：层1（max_num_batched_tokens 8240）——Task #25 基线出来后 A/B 一轮即知（预期 +15-20%，零风险）
2. **并行启动**：层2 Phase B（kernel 正确性，共享 GPU 可做）——层1 与层2 收益相乘
3. **层3 前置**：真实流量路由重采集（天级）→ 若集中度确认可拉（dense 覆盖能到 80%+）再投 router 微调（含全量 eval 质量门）
4. **不做**：层4 compile（DSV4 结构性受限，prefill 收益 ~5% 级）

**>2× 达成判断**：层1+层2 现实上限 **1.35-1.5×**；**过 2× 必须层3 成功**（dense 覆盖 ≥83%）+ 非 MoE 至少 1.25×。若用户不接受层3 的模型质量风险/训练周期，应将目标校准至 1.4-1.6×。
