## 4. P0 环境异常：与配置无关的随机 AR stall（本次窗口最重要发现）

### 4.1 现象

补充轮起 stall 呈**随机化**：同配置连续重跑结果全有或全无。逐迭代探针（40–300 迭代）显示：

- **干净运行**：全部迭代 0.12–0.30ms（max≤1.1ms），busbw 与基线一致；
- **stall 运行**：全部迭代 13–31ms，**量子化到整毫秒**（17.00/17.99/18.99/20.98…），运行内无一例恢复；
- 抽签在**通信建立时刻**决定，运行内（最长 300 迭代 / ~6 秒）保持不变。

### 4.2 排除项（全部做过对照实验）

| 假设 | 实验 | 结论 |
|---|---|---|
| v5 补丁引入 | v5on/v5off/prod 三库对照 | **无关**（clean 率统计无差异） |
| 通道数（4/8/16） | 探针 ×各配置 | 无关 |
| libncclpin CPU 亲和 | NO_PIN=1 对照 | 无关 |
| anemll-embed-8022 GPU 共占（04/03） | docker stop 后复测 | 无关（9/12 仍 stall） |
| CPU 争用 | top/uptime 四节点 | CPU 空闲（load <1） |
| NIC 层丢包/错误 | ip -s link 四网卡 | 零错误零丢包 |
| RDMA 重传/RNR | hw_counters 测试前后差分（7 次 stall 运行 280 AR） | **计数器零移动** |
| NCCL transport 报错 | DEBUG=INFO 日志 grep | 无任何 retry/timeout/warn |
| GPU 掉频/单节点掉队 | 四节点 dmon 1Hz 采样 | stall 期间四节点均 96% util、~2.5GHz 满频自旋 |

### 4.3 定位到的特征

- 精细分解探针（enqueue/GPU-event/host-wall 三路计时）：**enqueue 0.02ms、GPU event 18ms** → 延迟在 GPU 时间线内（NCCL kernel 自旋等数据），非 host 阻塞、非 launch 延迟；
- 17ms ≈ 4.096µs×2¹²（mlx5 重传超时指数 12 = 16.78ms）的量级，但 RDMA 重传计数器零移动 → 数据未丢失，是**到达慢**而非重传；
- 1ms 量子化 → 数据以 ~1ms 粒度推进（轮询/定时器粒度签名）；
- 取证确认 GDR=0（"Connected all rings, use ring PXN 0 GDR 0"）：本平台 IB 数据路径经 host staging（proxy 线程在数据路径内）；
- **随时间恶化**：18:18 约 25–30% 运行干净 → 18:31–18:45 约 20–33% → 18:47–18:52（大样本统计轮）：

| 配置 | clean / total |
|---|---|
| v5-ON 8ch | 0 / 10 |
| v5-OFF 8ch | 1 / 10 |
| 生产库 4ch（生产等价配置） | 0 / 10 |
| v5-ON 16ch | 1 / 6 |

- 采样器 /tmp/_slowround/ 于今日 14:22 起运行（phase-1 slow-round 调查）——**生产环境今日已存在 slow round 现象，时间线吻合**；本轮数据表明该现象已到"几乎必然发生"程度，且**4ch 生产配置同样中招**（历史认知"4ch 免疫"被推翻）。

### 4.4 结论与升级建议

**stall 为环境级（平台/织物/驱动层）故障，与 NCCL 库版本、通道数、环序完全无关。** 建议升级另查（优先级 P0）：

1. 交换机侧：PFC/ECN 配置、端口级拥塞与队列状态（1ms 粒度推进的签名指向交换机调度/队列行为）；
2. GB10 平台：GDR=0 情况下 host staging 路径（C2C + proxy 线程唤醒链路）、驱动 DVFS/空闲状态交互；
3. 与 _slowround 调查合并：本报告的 per-run 全有/全无特征 + 1ms 量化 + 无重传可作为该调查的关键约束条件；
4. 环境修复前，**一切微基准判定（含本报告 J1/J2/J3 的绝对值）不可作为 e2e 预估依据**。

## 6. v5 判定：No-Go（本次窗口）

**不进入生产上线流程，不出上线方案。** 理由：

1. **价值主张不成立**：v5 的意义在于"解锁 8/16 通道带宽"。干净窗口数据显示 8ch≈4ch（21.1 vs 21.6GB/s）、16ch 反而更差（13.0）、33.5MB prefill AR regime 三配置持平（~19.8GB/s）——本拓扑（4×200G 环、GDR=0）的 busbw 天花板不随通道数提升，替换库无收益；
2. **stall 功效未证实**：环境 stall 与库无关，v5 未表现出任何差异；
3. **环境不可判定**：P0 环境故障未修复前，任何 Go 判定无效。

**若未来重启 v5 评估的前置条件**：(a) P0 环境 stall 根因修复并复测稳定；(b) 重新审视根因假说（环序假说前提已被取证动摇，需先解释 v1b/v4/v5 各层对 node 级分配的实际作用）；(c) 在干净环境下重跑 W1 矩阵 + 正确性门。

v5 资产保留于四节点 /tmp/_ringopt/v5/（含全部日志与 results JSON），生产零接触，无需回滚。

## 7. QPS2 捷径结论：不采纳

- QPS2@4ch 与 @8ch 全部运行恒定 17–35ms，无一干净样本（虽受环境污染，但**无任何正向证据**）；
- 历史"QPS2 旧劣化数据"本就测在已坏的 8ch 上，不可靠；
- **不建议生产 env 采纳**。环境修复后如需复测，单独安排（成本已证明极低，~6 秒/臂）。

## 8. 33.5MB 档（threshold 4096 prefill AR regime）结论

干净窗口 v5-on 数据：4ch/8ch/16ch = 19.78/19.79/19.45GB/s（t4096 2.54–2.59ms）——**通道数对生产 prefill AR regime 无增益**，当前 4ch 采纳态即为该 fabric 的实际最优。生产 PR 增益预估：**0%**。
