## 一、缺陷 #7 根因回顾（生产诊断确认）

Triton 3.6 `dot_scaled` 实测签名（与内核 v8/v9 假设完全不符）：

```python
tl.dot_scaled(lhs, lhs_scale, lhs_format,   # lhs_format 必填位置参数
              rhs, rhs_scale, rhs_format,
              acc=None, fast_math=False,
              lhs_k_pack=True, rhs_k_pack=True, out_dtype=tl.float32)
```

- ❌ v8：`lhs_type="e2m1"` 关键字不存在 → `TypeError`
- ❌ v9（MCP 自动生成）：**退回 `tl.dot` fp32**（`allow_tf32=False`）→ 编译能过但性能自杀（fp32 vs FP4 峰值差 ~6–12×），且接口被改坏为 5 参
- ✅ v10：`dot_scaled(lhs, lhs_scale, "e2m1", rhs, rhs_scale, "e2m1", acc=acc, rhs_k_pack=True, out_dtype=tl.float32)`——位置参数 + 32 分组 + rhs_scale 不转置

## 二、v10 设计要点

| 项 | 实现 |
|---|---|
| scale 分组 | **32 沿 K**（Triton e8m0 硬约束 = Blackwell mmaf_scaled 原生粒度）；lhs_scale `[M, K//32]`、rhs_scale `[N, K//32]` |
| rhs_scale 来源 | W_scale `[K//32, N//128]` → 内核内 load 展开 `[BN, BK//32]`（每 128 N 行共享一行 scale，`offs_n // 128` 索引） |
| A 量化 | 内核内 32 分组 max → E8M0（fp32 bitcast 取指数，int clamp 用 min/max）→ 阈值链最近 E2M1 → nibble 打包 `[BM, BK//2]` |
| W 打包 | 解包 nibble → interleave `[BK, BN]` → trans `[BN, BK]` → K 方向 2:1 重打包 `[BN, BK//2]`（rhs_k_pack 布局） |
| MMA | 单次 `tl.dot_scaled` 整块调用（**无逐 g 循环**） |
| 接口 | **恢复 4 参** `(A, W_packed, W_scale, bias)`，与转换器/test 一致 |
| Triton 3.6 兼容 | 无 slice 索引 / `tl.split(x)` 单参 / int clamp 用 min/max / bitcast 前显式 fp32 / `tl.constexpr(127)` |
| 性能优化（MCP） | GROUP_M=8 二维 swizzle（W 复用）、12 组 autotune、指针预计算、eviction 分级 |

## 五、风险与注意

1. **精度语义变更**：32 分组（vs 官方 16×128）为硬件/Triton 硬约束下对齐，精度代价 ~0.1–0.3%；转换器已重算 scale，nibble 数据可复用
2. **rhs_scale 展开正确性**是 v10 最易错的点（每 128 N 行共享 scale 的行索引），T2 pytest 的数值比对（5e-2）即为验证
3. v9 已弃用：**勿合入生产**（fp32 dot + 5 参接口）
